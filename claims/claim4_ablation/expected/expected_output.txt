Expected output — Claim 4 (ablation)
====================================

Reference logs
--------------
The stdout for each ablation run is included (trimmed to the "Results (SARCP)"
banner) under:
    claims/claim4_ablation/eval_logs/<dataset>_act_<seed>_<variant>.txt
where <variant> is one of:
    _no_retrieve   -> config A  (retrieval OFF; post-processing and refine also off)
    _no_update     -> config B  (retrieval ON, post-processing OFF, refine off)
    _no_refine     -> config C  (retrieval ON, post-processing ON, refine off)
Config D (full CHAGent: retrieval + post-processing + refinement) is the base run
and its logs live with Claim 2:
    claims/claim2_generation/eval_logs/<dataset>_act_<seed>.txt

Note on config A: --no_retrieve routes through the branch in eval_chagent.py that
skips update() entirely, so retrieval-based post-processing does NOT run (and
refinement is forced off). The "Post-process: True" line printed in the
_no_retrieve logs is a mislabel — it reflects the unused --no_update flag, not
what actually executed.

Output format
-------------
Same two blocks as Claim 2 (Results (SARCP) with Precision/Recall/F1 +
component-wise breakdown, then Results (ACR Generation) with Precision/Recall/F1).

Expected trend
--------------
Generally F1(A) < F1(B) < F1(C) <= F1(D): retrieval gives the largest jump
(A -> B), retrieval-based post-processing helps further (B -> C via the base
retrieval path), and refinement (C -> D) adds a final, smaller gain. On a few
dataset/seed pairs refinement is roughly neutral or marginally lower (e.g. ibm
seed 3, cyber seed 4, t2p seed 3); this is expected per-seed variation and the
aggregate trend still holds.

Known gaps (config A / --no_retrieve)
-------------------------------------
Three config-A runs errored out and therefore have no metrics (marked
"(see note)" above): collected seed 4, overall seed 3, and t2p seed 3. The
included logs for these contain the traceback: --no_retrieve hits
get_srls(p, post_process=True) where a generated policy element is a plain
string rather than a dict (utils.py get_srls -> "AttributeError: 'str' object
has no attribute 'items'"), a data-dependent failure in that path. Re-run those
three cells (or use the other seed) to fill the config-A column.
