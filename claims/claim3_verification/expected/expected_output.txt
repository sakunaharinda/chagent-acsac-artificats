Expected output — Claim 3 (policy verifier)
===========================================

Reference logs
--------------
Verifier evaluation reports for three training seeds are included (trimmed to
the report section) under:
    claims/claim3_verification/eval_logs/ver_0.txt   (seed 0)
    claims/claim3_verification/eval_logs/ver_1.txt   (seed 1)
    claims/claim3_verification/eval_logs/ver_2.txt   (seed 2)

run.sh (eval_test.py) evaluates the PROVIDED seed-2 checkpoint, so its output
should match ver_2.txt. Only the seed-2 checkpoint is published on the Hub
(each verifier checkpoint is ~5 GB), so seeds 0 and 1 are reference-only: to
reproduce them, retrain with train_test_verifier_single_split.py --seed=0/1
(the verification training data is included).

Output format (what eval_test.py prints)
-----------------------------------------
  1) Binary classification report (negative = "correct" [label 11],
     positive = "any error"): precision / recall / f1-score / support.
  2) MCC: <matthews correlation coefficient> for the binary task.
  3) 12-class classification report over label ids 0..11 (ID2AUGS:
     0 allow_deny, 1 csub, 2 cact, 3 cres, 4 ccond, 5 cpur, 6 msub, 7 mres,
     8 mcond, 9 mpur, 10 mrules, 11 correct).

Interpretation
--------------

(and the full per-class breakdown in ver_2.txt) exactly, since evaluation is
deterministic (argmax over logits) on a fixed test set. The seed 0/1 rows show
the run-to-run spread; the paper's mean/SD across seeds {0,1,2} is aggregated
EXTERNALLY from these three values.
